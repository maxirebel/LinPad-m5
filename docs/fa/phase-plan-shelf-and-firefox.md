# فازبندی اجرایی «قفسهٔ قرنطینه» + فایرفاکس به‌عنوان مرورگر پیش‌فرض

> **دستگاه:** iPad Pro M5، ۱۲ گیگابایت، iPadOS 27.2 · **LinPad 1.5.0** (Alpine 3.21/musl)
> **این سند:** نقشهٔ اجرا با معیار پذیرش و دروازهٔ تصمیم. هیچ‌چیز هنوز اجرا نشده؛ منتظر دستور شروع.
> **فاز ۰** (تنظیمات + `phase0.sh`) قبلاً آماده شده است.

## ۰. دو تصمیم که ترتیب فازها را تعیین می‌کند

**تصمیم ۱ — فایرفاکس اول، ابزار بعد.** خواستهٔ شما «حذف ۱۲۸ و نصب نسخهٔ به‌روز به‌عنوان پیش‌فرض» است. به‌جای ساختن دو هفته ابزار و بعد تست، اول فایرفاکس را **دستی** نصب می‌کنیم (فاز ۱). اگر کار کرد، همان مسیر را در ابزار قفسه می‌ریزیم؛ اگر نکرد، قبل از هر هزینه‌ای می‌فهمیم و مسیر جایگزین (Alpine 3.24 با ESR 140 بومی) را انتخاب می‌کنیم. این یک **دروازهٔ تصمیم** است، نه یک ریسک.

**تصمیم ۲ — «پیش‌فرض» سه چیز است، نه یکی.** در این سیستم‌عامل سه مسیر جدا وجود دارد که یک مرورگر می‌تواند «پیش‌فرض» شود، و امروز هیچ‌کدام به فایرفاکس نمی‌رسد:

| مسیر | امروز چه می‌شود | برای فایرفاکس چه لازم است |
|---|---|---|
| کلیک روی لینک داخل اپ لینوکسی (`ish-open`) | `firefox-esr` را از PATH صدا می‌زند، وگرنه به میزبان برمی‌گردد (`wl-bridge/guest/ish-open`) | یک لانچر به نام `firefox-esr` در `/usr/local/bin` |
| درخواست باز کردن URL از سمت میزبان | `desktop.linux.urlHandler == "firefox"` را می‌خواند (`DesktopController+Linux.swift:132`)، ولی **هیچ‌جا این کلید نوشته نمی‌شود** → «Quick Preview» باز می‌شود | یک تغییر یک‌خطی در اپ: `!= "preview"` یا یک سوییچ در تنظیمات |
| «Open With» روی فایل HTML | از `MimeType=` فایل `.desktop` | یک `.desktop` با `text/html;x-scheme-handler/http;…` |

نکتهٔ مهم: کامنت `BrowserApp.swift` صریح می‌گوید «مرورگر لینوکسی، مرورگر دسکتاپ است و این نمای WebKit فقط برای پیش‌نمایش سریع است». یعنی **قصد طراح هم فایرفاکس بوده**، فقط کلید پیش‌فرض ست نشده. پس «پیش‌فرض کردن فایرفاکس» یک کار طبیعی است، نه یک هک.

## ۲. فاز ۱ — پایلوت فایرفاکس (دروازهٔ تصمیم)

### از کجا می‌آییم
| نسخه | منبع | حجم |

### هدف
بدون ساختن هیچ ابزاری، ثابت کنیم نسخهٔ **۱۵۳.۷.۰esr** (دبیان trixie-security، بستهٔ arm64، ۷۱٫۷ مگابایت، نصب ۲۸۱ مگابایت) روی این هسته پایدار و قابل استفاده است.

> **وضعیت: پیاده‌سازی شد.** فایل `personalize/phase1-firefox.sh` کل این فاز را روی خود آیپد انجام می‌دهد (بدون مک): حذف ۱۲۸، خواندن آخرین نسخه از ایندکس امنیتی دبیان، بررسی SHA-256، نصب در `/opt`، پروفایل تازه در `~/.mozilla-firefox-esr153`، لانچر، آیکون، و `--undo` برای برگشت.

### گام‌ها
۱. **بکاپ پروفایل** — `cp -a /root/.mozilla /root/.mozilla-backup-$(date +%F)` (مهاجرت ۱۲۸ → ۱۵۳ یک‌طرفه است).
۲. **حذف نسخهٔ قدیم** — طبق چک‌لیست پیوست الف.
۳. **ساخت رانتایم موقت** — جزیرهٔ glibc موجود یا `linpad-get island`؛ برای پایلوت، همان `/usr/lib/aarch64-linux-gnu` کافی است.
۴. **استخراج بسته در `/opt/firefox-esr-pilot`** — `dpkg-deb -x` (نیاز به `apk add dpkg`) یا `bsdtar`.
۵. **افزودن وابستگی‌های گمشده** — با `ld-linux --list` و افزودن بسته‌های دبیان (`libevent-2.1-7t64`، `libvpx9`، `libx11-xcb1`، `libxcb-shm0`، `libcairo-gobject2`، `libffi8`، و برای ویدیو `libavcodec61`).
۶. **لانچر موقت** — فایل `/usr/local/bin/firefox-esr` با loader صریح و پروفایل بهینه (پیوست ب).
۷. **تست** — ۱۰ سایت، ۵ تب، ویدیوی H.264، فونت فارسی، دانلود فایل، درگ‌اند‌دراپ، کیبورد.

| ویدیوی H.264 | پخش با صدا |

## ۳. فاز ۲ — هستهٔ قفسه

> **وضعیت: پیاده‌سازی شد (نسخهٔ ۱).** فایل `personalize/linpad-shelf`. یک تفاوت آگاهانه با طرح اولیه: در v1 **یک runtime مشترک و افزودنی** داریم (نه چند نسل موازی). دلیل: مدیریت نسل‌ها بیشترین ریسک باگ را داشت و سود عملی‌اش کم بود؛ هر اپ همچنان به‌طور کامل جدا و قابل حذف است. نسل‌بندی نسخه‌دار برای فاز ۲٫۵ می‌ماند.

### قرارداد (Contract)
```
/usr/lib/linpad-shelf/runtime/            رانتایم مشترک (v1: افزودنی، یک نسخه)
/opt/linpad-shelf/<name>/root/            پیلود اپ، تنها جای نوشتن
/usr/local/bin/<name>                     لانچر تولیدشده (تنها فایل بیرون از /opt)
/usr/share/applications/<name>.desktop    ورودی دسکتاپ
/var/lib/linpad-shelf/<name>/             دفتر ثبت: meta، files، dirs، extras
```

### قواعد سخت
- **صفر نوشتن در `/usr/lib`، `/lib`، `/usr/bin`، `/usr/share`** مگر فایل‌های تولیدی خودمان.
- اجرا با loader صریح و `--library-path` رانتایم — بدون symlink گلوبال، بدون `LD_LIBRARY_PATH` ارثی.
- داده‌های اپ با `XDG_DATA_DIRS` از overlay خوانده می‌شوند، نه با کپی در `/`.
- حذف = پاک‌کردن پوشه + سه فایل ثبت‌شده. هیچ وابستگی‌ای جا نمی‌ماند (رانتایم مشترک می‌ماند).
- **seed از جزیرهٔ موجود:** اگر `/usr/lib/aarch64-linux-gnu` از قبل هست (VS Code/Wine)، رانتایم از همان کپی می‌شود و دانلود دوباره لازم نیست؛ بعد از موفقیت فاز ۲ می‌توان جزیرهٔ گلوبال را بازنشسته کرد تا نسخهٔ تکراری روی دیسک نماند.

### معیار پذیرش
| معیار | حد قبول |
|---|---|
| نصب سه اپ مختلف | بدون خطا، بدون لمس مسیر سیستمی |
| حذف | `diff` فهرست فایل‌ها قبل/بعد = صفر |
| بوت و CPU بی‌کار | تغییر < ۲٪ نسبت به فاز ۰ |
| اپ خراب (deb بدساخته) | فقط overlay خودش خراب می‌شود، بقیه سالم |
| حجم | ≤ حجم نصب‌شدهٔ `.deb` + ۱۰٪ |

## ۴. فاز ۳ — فایرفاکس پیش‌فرض + حذف کامل قدیمی

> **وضعیت: پیاده‌سازی شد.** دستور `linpad-shelf migrate-firefox`. اگر فاز ۱ انجام شده باشد، همان نصب را بدون دانلود دوباره به قفسه منتقل می‌کند؛ وگرنه آخرین نسخه را از ایندکس امنیتی دبیان می‌گیرد. نسخهٔ ۱۲۸ و باقی‌مانده‌هایش حذف می‌شوند، لانچر همیشه `firefox-esr` است، و پروفایل تازه با prefs بهینه ساخته می‌شود. تنها اهرمی که بدون build ممکن نیست، کلید `desktop.linux.urlHandler` است (بخش ۰).

### سه اهرم «پیش‌فرض شدن»
۱. **لانچر هم‌نام + جایگزینی `ish-open`:** فایل `/usr/local/bin/firefox-esr` و یک `ish-open` نازک که مستقیم همان را صدا می‌زند (نسخهٔ اصلی بکاپ و با حذف اپ برگردانده می‌شود). این کار مسیر «کلیک روی لینک در اپ‌های لینوکسی» را کامل می‌کند، بدون نیاز به build.
۲. **پچ یک‌خطی اپ:** در `DesktopController+Linux.swift:132` شرط `== "firefox"` به `!= "preview"` تغییر کند، یا یک سوییچ «Open links in Firefox» در تنظیمات اضافه شود. این تنها تغییر سمت اپ در کل این فازبندی است و بدون آن، لینک‌های سمت میزبان همیشه در Quick Preview باز می‌شوند.
۳. **ورودی دسکتاپ:** `.desktop` با `MimeType=text/html;x-scheme-handler/http;x-scheme-handler/https;` تا در «Open With» اول بیاید.

### حذف کامل ۱۲۸ — تعریف «کامل»
حذف تنها با `apk del` تمام نمی‌شود؛ سه جای دیگر هم باید تمیز شود (جزئیات دستوری در پیوست الف):
- بستهٔ `firefox-esr` و فایل‌هایش،
- پروفایل قدیمی (بکاپ می‌شود، حذف نمی‌شود مگر بعد از مهاجرت موفق)،
- خط `firefox-esr` در `/etc/ishwl/app-scale` (باید بماند، چون لانچر جدید هم همان نام را دارد).

### معیار پذیرش
- `apk info -e firefox-esr` → خروجی غیرصفر (نیست).
- `ls /usr/lib/firefox-esr` → وجود ندارد.
- `which firefox-esr` → `/usr/local/bin/firefox-esr`.
- `firefox-esr --version` → 153.7.
- کلیک روی لینک از foot → پنجرهٔ فایرفاکس، نه Quick Preview.
- بوت و CPU بی‌کار: بدون تغییر محسوس.

## ۵. فاز ۴ — استور

> **وضعیت: نیمه‌پیاده‌سازی.** سمت مهمان کامل است (`linpad-shelf list --json`). سمت اپ نوشته شد (`Apps/Shelf/ShelfApp.swift` + ثبت در `BuiltinApps`/`AppID`) ولی **کامپایل نشده**، چون این ماشین مک/Xcode ندارد. تا build نشود، این قابلیت فقط از ترمینال در دسترس است.

## پیوست الف — چک‌لیست حذف کامل فایرفاکس ۱۲۸

```sh
# ۰. بکاپ پروفایل (اجباری)
cp -a /root/.mozilla /root/.mozilla-backup-$(date +%F)
du -sh /root/.mozilla-backup-*

# ۱. چه چیزی نصب است؟
apk info -e firefox-esr && apk info -v firefox-esr
apk info -L firefox-esr | head -20          # فایل‌های بسته

# ۲. حذف بسته
apk del firefox-esr

# ۳. باقی‌مانده‌ها را چک کنید (باید خالی باشد)
ls -d /usr/lib/firefox-esr 2>/dev/null || echo "lib: clean"
ls /usr/share/applications/firefox* 2>/dev/null || echo "desktop: clean"
command -v firefox-esr || echo "path: clean"

# ۴. مواردی که عمداً می‌مانند
grep firefox /etc/ishwl/app-scale           # خط مقیاس: باید بماند
ls /root/.mozilla                            # پروفایل: باید بماند (برای مهاجرت)

# ۵. بعد از نصب نسخهٔ جدید
firefox-esr --version
grep -m1 '"version"' /opt/firefox-esr-pilot/usr/lib/firefox-esr/application.ini
```

نکته: اگر روزی خواستید برگردید، `apk add firefox-esr` نسخهٔ ۱۲۸ را برمی‌گرداند (تا وقتی مخزن 3.21 در دسترس است) — پس این عملیات برگشت‌پذیر است.

## پیوست ب — پروفایل «به‌روز اما بهینه» برای ۱۵۳.۷

این مقادیر باید **داخل overlay خود فایرفاکس** نوشته شوند (نه در `/usr/lib/firefox-esr`)، تا با حذف اپ، حذف شوند.

| کلید | مقدار | چرا |
|---|---|---|
| `dom.ipc.processCount` | ۱ | هر پروسهٔ اضافه یک ترجمهٔ کامل `libxul` می‌خواهد |
| `fission.autostart` | false | همان دلیل |
| `security.sandbox.content.level` | ۰ | هسته seccomp ندارد (`kernel/misc.c`) → وگرنه تب‌ها کرش می‌کنند |
| `media.mediasource.webm.enabled` | false | H.264 ارزان‌تر از VP9/AV1 روی شبیه‌ساز |
| `media.av1.enabled` | false | همان |
| `layout.css.stylo-threads` | ۲ | هر ترد ~۱٫۳MB هزینهٔ میزبان |
| `javascript.options.mem.gc_max_helper_threads` | ۲ | همان |
| `browser.cache.memory.capacity` | ۶۵۵۳۶ | ۱۲ گیگابایت رم |
| `image.mem.surfacecache.max_size_kb` | ۲۶۲۱۴۴ | همان |
| `browser.tabs.unloadOnLowMemory` | true | محافظ در فشار حافظه |
| `toolkit.cosmeticAnimations.enabled` | false | هر انیمیشن یک بازترسیم نرم‌افزاری |

و از سمت اپ (کار «موتور» در گزارش فازها، جدا از این سند): `pcache` ۲۵۶ و `JIT arena` ۵۱۲ — این‌ها بیشترین اثر را روی «روانی» دارند و بدون build نمی‌شوند.
